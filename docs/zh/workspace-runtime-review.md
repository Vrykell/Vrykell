# 工作区运行修复复查

日期：2026-10-27

## 设计边界

共享模型统一标签、分组、窗格放置和带保护的生命周期操作，持久化策略仍按资源性质区分。打开资源时新建或选中其标签，只有显式拆分才改变组合。文档、比较和未保存草稿属于活动工作区恢复，不属于会话历史。前端两个历史写入入口裁掉文件引用，原生写入边界拒绝文件成员，初始化迁移旧记录：删除纯文件记录，混合记录保留会话成员、裁剪布局并修复焦点。迁移不修改原文件、对话正文或终端历史。

纯文件分组不提供归档；最后一个标签关闭后清理分组及持久元数据。分组卡片沿用已有连接外形和配色。资源标题使用有界共享菜单，单行省略，保留完整无障碍名称和主题提示。记忆页使用普通分区设置行，提供状态/刷新和明确的 AI 整理按钮；整理通过正常授权路径打开简短标题的对话。模态命令独占原底部状态行，继承该行字体，不与其他元数据或模式文字争抢空间。

## 事故发现与修复

| 证据 | 原因与修复 |
| --- | --- |
| 结构化日志和用户提供的最大更新深度调用栈指向放置清理与隐藏窗格 effect | 提供树级状态更新反复触发插槽所有者；隐藏取消又依赖每次新建的回调。改为按资源的外部订阅、稳定清理归属、按状态触发的 effect 和尺寸不变时的更新保护。 |
| 复制的本地工作区快照包含超过 1,100 个引用，而用户只主动打开了少数标签 | 启动生命周期重放用新标识重复恢复空草稿。共享执行中及已完成的恢复任务，按稳定标识批量恢复草稿，加载期间暂停协调，最后统一提交容器。 |
| 隐藏空对话挂载编辑器，全局变化遍历无关所有者 | 对话内容首次展示才挂载，之后保留；缩小运行订阅范围并建立资源索引，串流文本不再协调全部容器。 |
| 原生资源变化后聚合开始页消失 | 协调同时自动收集了未放置资源。现在只裁掉失效的已有放置，并维护空工作区的开始目标。 |
| 打开文件返回执行凭证错误 | 文件和比较接口绕过公共授权调用封装。统一经过封装，并在架构检查中禁止原始调用导入。 |
| 文件分组进入会话历史 | 布局快照被复用时缺少会话持久化边界。过滤两个前端写入口、原生拒绝文件、清理旧记录显示并迁移存储元数据。 |
| 打开文件静默插入分屏 | 资源呈现复用了组合插入路径。呈现和切换改为选择所属标签，只有显式放置才插入窗格。 |

本地恢复先建立完整备份，再清理重复的默认空引用；排除了已分组、已选中、已命名、有草稿或有内容的资源。该恢复与提交的应用行为分开，备份不纳入版本控制。
