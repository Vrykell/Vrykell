# 连接配置

主机管理和资源监控共用一个主机工作区。列表与卡片布局会记忆选择；资源占用开关仅在当前工作区活跃时启用采集。收藏、标签与文件夹筛选可以独立组合。所有视图中的收藏均使用黄色实心星标。新建或编辑已保存主机时打开完整页面，顶部保留保存操作，收藏按钮没有背景。分组标题位于紧凑行式卡片之外，环境变量与两类备注各自独立，转发和连接行为收在高级选项中，测试与删除操作位于表单内容末尾。端口留空默认为 22，名称留空使用目标地址。可以选择已有分组或输入新分组，也可以选择已有标签或创建具有稳定彩色圆点的新标签。按标签分组时，同一主机可以出现在多个分组。主机和分组均不提供拖动排序。

筛选栏和分组胶囊随主机结果共同滚动。标签选项展开后占用正常布局空间，不遮挡下面的控件；没有标签时禁用空筛选。编辑页使用公共输入框样式、四项认证选栏和彩色可移除标签胶囊。环境变量初始保留一行可选空输入，删除全部行后，添加按钮上方不会残留多余分隔线。

主机列表移除所有行分隔线，保持公共列表的紧凑行高。分组筛选使用 32 像素控件，其余工具栏操作采用公共紧凑密度。视觉回归同时检查深浅主题及正常、125% 显示缩放，不再只对照未缩放截图。

主机列表行始终不折行，窄布局省略或隐藏次要信息。卡片采用紧凑尺寸，选中后显示中性背景。资源读取失败可以展开公共错误详情并重试，指标菜单保持在视口范围内。

## 端口转发

独立转发工作区按已保存主机分组，管理具名的本地、远程与动态规则。编辑使用公共输入框和三项类型选栏。规则随主机持久化；旧转发字符串保留端点与连接时启动偏好。第一次独立启动旧规则前先迁移，避免后续连接仍由终端客户端重复监听。

启动与停止控制真实的认证转发会话，而非终端标签。本地规则把设备监听端口经服务器连接到目标；远程规则把服务器监听端口连接到本机目标。动态规则接受有界的、无需认证的 SOCKS5 TCP 协商。默认仅监听回环地址；选用公开绑定地址后，对应网络可以访问监听端口。每条规则最多允许 64 个并发客户端，整个应用最多允许 32 条运行中规则。缓冲区与握手时长均有限制。

复用已有保存凭据、临时认证缓存、主机密钥验证与代理链路。标准跳板链路支持文件浏览、资源监控及受管转发。连接时启动的规则会在终端连接就绪后启动。受管转发独立运行，直到手动停止、主机或端点改变、规则或主机被删除，或应用退出；修改或删除引用的跳板主机也会停止依赖它的转发。修改名称和启动开关不会中断直连监听。浏览器模拟验证编辑与生命周期调用，隔离的回环协议服务器验证两跳兼容性。

代理选择、环境变量、备注和 AI 备注随连接保存到数据库。代理配置支持 SOCKS5、HTTP CONNECT、可选的设备默认代理，以及显式直连。代理密码使用现有平台凭据存储，不回传编辑器；密码留空保存时保留已有凭据。删除被选用的代理后会明确报错，不会悄悄改为直连。已保存的跳板链路仅在第一层跳板连接中配置代理。终端的旧跳板地址模式保留原有的代理组合限制。

终端通过远程会话请求发送环境变量，不修改本地进程变量；服务器必须允许这些变量。最多支持 64 个不重复变量，总量不超过 32,768 字节；变量名必须为标识符，值不能包含换行或空字节。两种备注分别限制为 16,384 个 UTF-8 字节。关联该主机的 AI 请求将备注作为用户提供的上下文，而非权限授权。环境变量和备注不是凭据存储，请勿填写敏感信息。

代理凭据按代理协议发送到代理端，这些代理协议的初始交换不加密。请使用可信本地代理或受保护网络。目标主机密钥仍须验证。终端代理辅助进程仅接受经过校验的标识符和目标地址，不在命令参数中携带凭据，并限制协议头大小和握手时长。诊断记录脱敏环境变量内容、备注和凭据。

验证覆盖数据库往返、远程参数转义、认证方式、协议握手、异常响应、超时上限和凭据序列化。浏览器测试对照深浅主题和宽窄布局，保存并重新打开完整配置、管理代理，并验证独立光标闪烁设置。终端和输入法模拟光标默认不闪烁，可在字体与显示设置中分别开启。

## 跳板链路与交互网关

目标主机可以选择已保存连接作为跳板；被引用的连接也可继续引用其他跳板，最多八层，拒绝循环、缺失引用及与跳板地址冲突的配置。每层独立保留账号、密钥、已保存密码和临时认证。文件连接逐层验证主机密钥，通过加密转发通道完成目标握手。修改连接或清除认证会淘汰缓存文件通道，包括依赖链路；通道绑定包含每层配置及凭据版本。目标连接释放时取消整条转发链路。

交互终端继续使用系统客户端。临时配置仅包含每层的非敏感地址和密钥设置，并启用主机指纹确认；密码在终端中交互输入，不进入命令参数或临时文件。终端读取器退出时删除该文件。原有逗号分隔的跳板地址仍然可用，后台地址链路使用显式账号或导入器已经支持的基本主机别名设置。需要独立密码及临时私钥口令时，请使用已保存连接。

认证服务沿用共享弹窗。服务器密码与私钥解密口令按第一层跳板到目标主机推进，各层凭据独立保留。“服务器交互验证（MFA）”在每个端点的一次握手中完成整条目标链路，支持多轮、多字段及服务器指定的明文或掩码输入；发送凭据前先确认未知指纹，已知指纹变化仍直接拒绝。回答提交后清空，不缓存或重放。

文件浏览和监控在保留的目标认证连接上串行执行，刷新不会再次请求验证码。关闭最后一个依赖终端、清除认证、修改端点或代理，以及退出应用都会淘汰该连接。连接失效后要求重新认证，修改操作不自动重放。传输任务与受管转发仍需独立认证，不复用这条阻塞服务连接。外部审批和仅有资产菜单的流程仍由终端处理，网关菜单不意味着支持转发、SFTP 或资源访问；此类网关应保持关闭 shell 集成。

服务失败显示原始出错端点及阶段：握手、主机指纹校验、认证、打开 SFTP 或资源采集。外层服务错误保留出错跳板的信息，不将其替换为目标机。

Windows 桌面后端使用随应用内置的加密库，支持现代密钥及密钥交换。协议回归同时使用同一有限域算法重复直连和跳板握手，以发现间歇性密钥交换失败，并覆盖认证与服务行为。

从网关进入 shell 后，如果残留鼠标、焦点通报或应用光标模式，可在终端右键菜单选择“重置终端输入模式”。该操作保留屏幕和连接，不发送远程命令。受支持桌面平台的原生键盘协商由终端解析器处理，诊断标记只记录模式元数据，不记录输入内容。

可通过 `uv run --with paramiko python scripts/test-ssh-jumps.py` 运行隔离协议验证。测试使用临时密钥、回环监听及独立信任文件，覆盖独立密码和密钥认证、两层跳板与目标机的双因素验证、服务并发复用而不重新认证、文件、资源、转发、未知及变化的指纹、取消、错误回答、客户端启动配置和连接清理。
