# 2026-10-21 集成审查

> 本文保留修复前的审查快照。后续修复与验证见[集成修复记录](integration-fixes-2026-10-21.md)。

本次按**尚未完成的集成**审查，比较合入前 dev `91abc88` 与当前 `b7c4f68`（198 个文件）。审查范围为新增 ACP、模型配置、用量统计、授权机制，以及这些改动对近期回归修复的影响。此次只交付审查与证据，没有调整业务实现，也没有提交或推送。

## 必须优先处理

### R1 · P1 · 本对话授权变成全局授权：已复现的旧功能回归

位置：`src-tauri/src/agent/permissions.rs:299`、`:626`；`src/features/agent/services/toolPolicy.ts:28`；`src/features/chat/stores/chat.ts:377`。

合入前的临时授权为 `Map<conversationId, Set<tool>>`。当前后端只有全局 `session_grants`、`shape_grants`，授权请求与批准请求都不携带对话身份。A 对话允许 `npm run` 后，B 对话的同类请求直接获准；关闭一个对话或改变其执行目标又会撤销所有对话的授权。这与菜单“本对话允许”的承诺不一致。

探针结果：B 对话预期 `asked: true, proceeded: false`，实际 `asked: false, proceeded: true`。探针使用真实前端与测试 IPC 策略；后端无对话维度这一根因由代码交叉确认。应将对话身份贯穿批准、判定、撤销，授权按对话保存，执行目标变化只撤销所属对话。危险操作原生确认仍应先于临时授权。

### R2 · P1 · Windows 普通可执行文件多收到一个路径参数

位置：`src-tauri/src/agent/acp.rs:114`。

`launch_command` 已将解析后的路径作为启动程序，却又把同一路径插入参数列表首位。配置普通 `.exe` 时，程序收到错误的第一个业务参数。通过实际启动 `node --version` 验证，运行时把自身二进制当脚本读取，以 `SyntaxError` 退出。现有内存传输测试覆盖不到启动包装。

应保持原始参数列表，只对命令脚本使用解释器包装，并分别测试可执行文件、命令脚本、带空格路径。该问题属于新增 ACP 的实现缺陷。

### R3 · P1 · 服务器编辑保存后立即离开，会丢失修改

位置：`src/features/settings/pages/harnessPage.tsx:49`。

编辑弹窗的保存只更新页面状态，真正写盘延迟 600ms；页面卸载清除计时器，却没有冲刷待保存内容。新增服务器后立刻关闭设置，探针等待 5 秒，`acp_harness_save` 调用数仍为 0。立即“连接”也可能读取尚未更新的配置文件。

应复用现有设置保存队列及页面级反馈，保存成功后再关闭编辑弹窗或连接；离开页面时冲刷，失败保留草稿与重试入口。不能仅靠一个额外“保存列表”按钮补救自动保存语义。

### R4 · P1 · 旧密钥迁移失败仍可能删除源密钥：代码确认

位置：`src-tauri/src/agent/ai.rs:247`。

旧家族密钥迁移到端点密钥时，`carried = true` 不依赖写入成功；只要存在该家族模型，随后就删除旧账户。新密钥写入失败且原本没有端点密钥时，唯一可用的源密钥会被删除。此次未对真实凭据做故障注入。

应逐个确认目标已存在或写入成功，再删除源密钥；任一失败都保留源，供下次重试。另外 `set_provider_key` 写入失败只打印日志并正常返回，前端会关闭弹窗并显示已配置，也需要将错误返回给保存流程。

### R5 · P1 · 关闭 ACP 页签没有可靠结束进程：代码确认

位置：`src-tauri/src/agent/acp.rs:807`、`:618`。

事件泵将弱引用升级为强引用后，持有它等待 `next_event().await`。关闭页签仅从运行时映射移除客户端；安静的进程仍被事件泵持有，`kill_on_drop` 无法触发。每次收到新事件，循环还会再次升级引用。重启、关闭后重新连接会累积后台进程；正在运行的请求也持有客户端。

应让会话显式拥有可取消的事件泵与进程关闭流程，关闭时取消请求、处理待审批项并结束进程，而不是依赖最后一个强引用自然释放。需要真实子进程退出测试，内存协议测试不足以证明关闭完成。此次没有将真实外部 agent 的退出行为记作已验证。

## 新功能交互尚未收口

### R6 · P2 · 工作目录没有跟随当前聚焦窗格

位置：`src/features/workspace/stores/workspace.ts:333`。

当前逻辑始终取活动会话的 `firstLeaf`，从其他页面打开时还把标签数组末项当作最近使用会话。探针在右窗格聚焦时得到左窗格目录。ACP 在本机运行，也不应把 SSH 的远端目录静默当成本机目录。

应复用工作区的聚焦目标解析，捕获明确的本地目录；从非终端页面进入时沿用最后一个有效本地上下文，或要求选择项目。已打开的会话应保持自己的目录，并在页内可见。

### R7 · P2 · 切换页签丢草稿与阅读位置

位置：`src/features/terminal/components/TerminalView.tsx:118`；`src/features/chat/components/HarnessView.tsx:121`。

ACP 页面在非活动状态被卸载，草稿却保存在组件局部状态。探针输入 `unfinished draft`，切走返回后为空；阅读位置从 300px 回到 0。消息仍在状态仓库，但页面的交互状态没有保存。

应复用现有对话草稿存储，并按内部会话保存阅读位置、焦点及必要的输入状态。单例页的外壳和内部会话状态必须独立于页面挂载生命周期。

### R8 · P2 · 流式回答不持续跟随底部

位置：`src/features/chat/components/HarnessView.tsx:156`。

跟随效果只依赖交流条数和 `pending`；同一回答追加内容不会改变条数。即便再次触发，先根据增长后的高度判断是否贴底，也无法判断用户此前是否在底部。探针从底部开始接收连续文本，最终离底部 5298px。

应复用既有对话的滚动跟随机制，记录内容变化前的跟随状态，对流式增量与布局变化更新，同时保留用户上滚暂停的行为。

### R9 · P2 · 从设置中搜索用量，目标页面仍被设置遮住

位置：`src/features/settings/services/registry.ts:142`。

用量搜索结果只激活工作区页签，没有关闭设置屏幕。探针在设置开启时调用搜索结果的真实动作，目标已挂载但不可见。ACP 设置的连接动作已做过同类修补，用量入口仍遗漏。

应统一“打开工作区页面”的导航动作，确保入口切换屏幕、激活目标、恢复焦点的行为一致。

## ACP 单例页与整体风格建议

建议采用**一个 ACP 工作区页 + 页内会话标签**，复用编辑器的单例页和共享 `FolderTabs` 模式。当前只是“每个服务器一个工作区页”，与编辑器的单例语义不同。单例的是入口和页面容器，不是所有服务器共用一个进程或一份对话。

| 位置 | 建议行为 |
| --- | --- |
| ACP 入口 | 总是打开或聚焦同一个 ACP 页；没有会话时在页内显示可连接服务器及配置入口 |
| 页内会话 | 保留各自服务器、项目目录、消息、草稿、滚动和运行状态；使用共享页签交互 |
| 设置 | 只维护服务器配置与探测；连接后进入同一个 ACP 页；提供一致的自动保存反馈 |
| 新建会话 | 明确选择服务器及项目；不把“切换可见会话”做成“销毁连接” |
| 关闭 | 区分关闭会话与关闭页面；有运行任务、待审批或未发送草稿时采用现有保护模式 |
| 用量 | 保留独立统计页；可从 ACP 与本机对话进入同一统计入口并定位来源 |

视觉核查覆盖 1240×800、760×700。会话复用 `AiBlock`、输入控件和主题变量，设置也使用既有分组，基础方向一致，不需要另造一套视觉。仍需统一：

- `AcpLauncher` 应复用公共弹窗键盘与焦点管理；当前只有手写键盘分支，没有焦点约束与恢复，空态也没有可点击的配置入口。
- `ChatComposerShell` 当前仅被 ACP 使用；本机对话仍保留另一份输入外壳。后续通过共享组件收口，保留已有测试钩子与行为。
- ACP 的连接失败、探测失败与配置载入失败应走共享错误展示及重试；当前两处载入失败被转为空列表，易被误认成没有配置。
- 参数以空格连接、再按空白拆分，编辑含空格参数会破坏原始数组；参数输入需要保留边界。
- 新增 Rust 错误文案和多处注释仍直接使用中文，不符合英文源文案与注释规则；新增 ACP 日志还直接记录 `cwd`，不符合用户路径脱敏要求。收口时应一起修正。
