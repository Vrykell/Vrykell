# 工作区统一底层

终端、代码、AI 和聚合工作区使用同一套持有布局的标签、按区域划分的分组、选择状态与生命周期契约。标签栏中的每个内容行都指向真实容器，单窗格标签也不例外。资源句柄只提供展示信息，不拥有布局。

## 当前模型

```
领域 store                  权威工作区层                          共享 UI
终端标签 / 窗格       ->   WorkspaceContainer { 区域、布局、   ->   useWorkspaceContainerTabs
文档 / 比较                焦点、分组、历史 }                FolderTabs -> GroupedTabList
对话 / 代理                WorkbenchSnapshot { 标签、分组、         WorkspacePaneCanvas
                           选择、顺序 }                             ResourceContent 宿主
                           |
                           +-> paneTree / paneLayout（树操作与几何）
                           +-> workspaceHistory（引用快照与串行写入）
```

- 容器拥有放置位置；原生 store 拥有进程、缓冲或对话内容。一个资源在每个区域最多一个放置，另可在聚合区域有一个放置。
- 标签栏的每个内容行都来自容器。工具页和开始页仍是单例，只参与标签栏排序。
- 工作区快照是唯一持久化的标签、分组、选择和顺序状态。区域 store 只暴露当前容器的只读投影，不持有第二套布局。
- 窗格操作共用 `paneTree`、`paneLayout` 和 `WorkspacePaneCanvas`；终端存储布局和原生会话 payload 只在持久化边界转换。
- 关闭、删除、归档、拆出、合并和恢复都走同一套资源协议和历史队列。

## 归属与边界

| 职责 | 权威实现 | 边界适配 |
| --- | --- | --- |
| 标签标识、区域、标题、焦点窗格、分组归属 | `model/workbench.ts`、`stores/workbench.ts` | 原生资源保留进程、文档和对话标识 |
| 二叉窗格树、遍历、替换、折叠删除和比例更新 | `src/core/paneTree.ts` | `WindowLayout` 是同一棵树在终端叶子上的实例；放置时转换为资源引用 |
| 窗格几何与放置 | `src/core/paneLayout.ts` | 终端存储格式转换和响应式适配接入同一个画布 |
| 资源能力、激活、关闭守卫、删除和序列化 | `model/paneResource.ts`、`services/workspaceResources.ts` | 终端进程/历史、文档缓冲、比较、对话和代理引用 |
| 区域分组、标签栏排序与操作 | `useWorkspaceContainerTabs`、`GroupedTabList` | 各领域只提供图标、标题、创建和系统页面操作 |
| 关闭、撤销、拆出、合并、整组删除/归档与同步 | `services/workbench.ts` | 终端所有权迁移保留稳定的窗格标识 |
| 版本化快照与历史写入队列 | `stores/workbench.ts`、`services/workspaceHistory.ts` | 现有原生会话记录和只含引用的工作区历史记录 |

共享的 `workspace-containers-v2` 快照保存容器、窗格引用、区域分组、各区域选择和分组/未分组标签交错顺序。它是唯一的工作区布局记录：不再读取旧区域布局键或旧导航顺序。区域 store 只是当前容器的只读投影，不拥有独立的区域布局。原生会话加载完成前，协调和快照写入不能丢弃暂未就绪的引用。

原生终端会话 payload 是当前历史记录使用的边界格式。进入恢复流程前验证比例有限、深度/数量有界、终端元数据有效、窗格标识唯一。遍历、比例更新和几何计算使用公共算法。历史记录中的 `workspace` 类型只是元数据，不是原生页面或进程所有者。资源仓库和单例工具页面仍属于各自领域；侧栏是现有对话内容宿主的一种放置方式。

## 资源呈现路由

所有创建资源或把资源移入工作区的动作使用同一套呈现规则。当前区域不是聚合工作区时，在资源的原生区域激活它：文件进入代码工作区，终端打开进入终端工作区，对话或代理进入 AI 工作区。在聚合工作区打开资源时，新建独立标签或激活该资源已有的标签，保留其他标签的布局。资源切换菜单也遵循此规则。只有明确执行拆分操作，才把窗格插入当前组合。

该规则覆盖首选编辑器/终端打开文件、文件面板新建标签、AI 侧栏对话移回工作区，以及 SSH 与命令历史终端启动。路由完成后，资源激活仍由原生所有者负责。

## 窗格操作与分屏流程

所有区域的窗格右键菜单使用同一顺序：拆分标签、更换窗格位置、将窗格移至新标签、移除窗格。单窗格仍显示这些动作，不可用的移动/移除动作禁用。窗格放大和按终端类型拆分已从右键菜单移除。终端窗格随后追加复制/粘贴、运行中命令和 SSH 操作；只剩一个终端时显示关闭该终端的动作。标签操作菜单也提供同一组公共窗格动作。

更换窗格位置使用共享落点模式：计算覆盖层前先移除正在移动的窗格，`moveWorkspacePane` 再把同一窗格标识插回所选落点。移动后保持该窗格焦点，并通过现有工作区投影持久化终端顺序。

分屏始终是显式落点操作，最多四个窗格。聚合工作区拆分终端时打开共享的拆分资源菜单（未放置的现有资源、新建终端/文件/对话、文件选择器或代理），不再默认创建终端。原生终端分屏仍先选落点并继承聚焦终端类型，终端类型选择器保留为原生终端动作。全局快捷键遵循同一规则：聚合工作区快捷键打开拆分菜单，原生终端快捷键保留继承类型或直接拆分行为。

## 生命周期与历史

切换标签恢复其完整窗格树和焦点。在原生工作区选择已有资源会打开或选中其所属容器；聚合工作区的资源切换按钮同样打开或激活资源所属标签，不隐式合并窗格。拆分通过显式落点操作完成。拆出和合并保留窗格/资源标识与实际内容宿主；终端 effect 依赖稳定的窗格标识，持久化回调读取当前所有者。

整组变更先完成所有关闭守卫。删除组通过资源协议删除每个成员，再移除分组和历史元数据。删除文档成员只关闭视图，不删除磁盘文件；批量删除对话不会自动创建替代对话；删除代理成员会忘记本地持久会话引用。归档是单独确认的操作，保留原分组与可恢复历史。存储失败通过持久错误通知提供重试、详情和关闭。

终端拆出/合并会将后续历史写入排在所有权迁移之后。数据库事务只移动选中窗格的命令块和聊天。删除混合组中的终端窗格只删除该窗格历史，不连带删除兄弟窗格。合并源会话在迁移成功后才删除。内存聊天使用同一窗格标识迁移；历史引用会找到已迁移窗格当前的所有者。

历史写入同时按活动容器和持久历史标识串行化，覆盖恢复到另一个活动容器的情况。窗格和历史标识使用有界生成值，不再拼接文档路径。关闭、自动保存、归档、删除共享队列。关闭后重试，以及同名活动容器标识被复用时，仍使用捕获的历史身份。删除抑制检查入队时捕获的请求标识；重新打开时清理对应抑制和 writer 缓存。会话历史只保存终端、对话和代理的引用及布局元数据，不包含文件、比较、草稿、正文或凭据。活动工作区恢复保留完整文件引用和草稿守卫，与会话历史分别处理。前后端写入拒绝文件成员；初始化时删除旧的纯文件历史，并从混合记录裁掉文件窗格、修复焦点。纯文件分组不提供会话归档。

## 验证约定

`npm run test:workbench` 对 `vitest.workbench.config.ts` 明确列出的公共底层要求**语句、分支、函数、行四项覆盖率全部 100%**。范围包含泛型树/几何、工作区模型/store/生命周期、资源/历史适配、反馈 store 和公共标签 provider。不使用源码覆盖忽略指令或排除未覆盖代码来达标。这个门禁针对统一底层，不代表无关应用功能或原生代码也有 100% 覆盖率。

单元回归覆盖所有区域、独立布局、异常快照、加载屏障、公共操作、守卫、历史队列、删除抑制、重试、局部排序、原生所有权迁移和进程宿主保留。浏览器回归覆盖四区域的分组创建/改名/成员归属/折叠/颜色/确认/删除、窄宽布局、聚合恢复，以及终端合并/拆出不重启进程。原生测试覆盖事务迁移、兄弟窗格安全删除、分组局部排序和历史元数据验证。
