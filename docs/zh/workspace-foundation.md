# 工作区统一底层

终端、代码、AI 和聚合工作区使用同一套持有布局的标签、按区域划分的分组、选择状态与生命周期契约。标签栏中的每个内容行都指向真实容器，单窗格标签也不例外。资源句柄只提供展示信息，不拥有布局。

## 当前模型

```
领域 store                  权威工作区层                          共享 UI
终端标签 / 窗格       ->   WorkspaceContainer { 区域、布局、   ->   useWorkspaceContainerTabs
文档 / 比较                焦点、放大、分组、历史 }                FolderTabs -> GroupedTabList
对话 / 代理                WorkbenchSnapshot { 标签、分组、         WorkspacePaneCanvas
                           选择、顺序 }                             ResourceContent 宿主
                           |
                           +-> paneTree / paneLayout（树操作与几何）
                           +-> workspaceHistory（引用快照与串行写入）
```

- 容器拥有放置位置；原生 store 拥有进程、缓冲或对话内容。一个资源在每个区域最多一个放置，另可在聚合区域有一个放置。
- 标签栏的每个内容行都来自容器。工具页和开始页仍是单例，只参与标签栏排序。
- 工作区快照是唯一持久化的标签、分组、选择和顺序状态。区域 store 只暴露当前容器的只读投影，不持有第二套布局。
- 窗格操作共用 `paneTree`、`paneLayout` 和 `WorkspacePaneCanvas`；终端存储布局和原生会话 payload 只在持久化边界转换。
- 关闭、删除、归档、拆出、合并和恢复都走同一套资源协议和历史队列。

## 归属与边界

| 职责 | 权威实现 | 边界适配 |
| --- | --- | --- |
| 标签标识、区域、标题、焦点/放大窗格、分组归属 | `model/workbench.ts`、`stores/workbench.ts` | 原生资源保留进程、文档和对话标识 |
| 二叉窗格树、遍历、替换、折叠删除和比例更新 | `src/core/paneTree.ts` | `WindowLayout` 是同一棵树在终端叶子上的实例；放置时转换为资源引用 |
| 窗格几何与放置 | `src/core/paneLayout.ts` | 终端存储格式转换和响应式适配接入同一个画布 |
| 资源能力、激活、关闭守卫、删除和序列化 | `model/paneResource.ts`、`services/workspaceResources.ts` | 终端进程/历史、文档缓冲、比较、对话和代理引用 |
| 区域分组、标签栏排序与操作 | `useWorkspaceContainerTabs`、`GroupedTabList` | 各领域只提供图标、标题、创建和系统页面操作 |
| 关闭、撤销、拆出、合并、放大、整组删除/归档与同步 | `services/workbench.ts` | 终端所有权迁移保留稳定的窗格标识 |
| 版本化快照与历史写入队列 | `stores/workbench.ts`、`services/workspaceHistory.ts` | 现有原生会话记录和只含引用的工作区历史记录 |

共享的 `workspace-containers-v2` 快照保存容器、窗格引用、区域分组、各区域选择和分组/未分组标签交错顺序。它是唯一的工作区布局记录：开发阶段不再读取旧区域布局键或旧导航顺序。区域 store 只是当前容器的只读投影，不拥有独立的区域布局。原生会话加载完成前，协调和快照写入不能丢弃暂未就绪的引用。

原生终端会话 payload 是当前历史记录使用的边界格式。进入恢复流程前验证比例有限、深度/数量有界、终端元数据有效、窗格标识唯一。遍历、比例更新和几何计算使用公共算法。历史记录中的 `workspace` 类型只是元数据，不是原生页面或进程所有者。资源仓库和单例工具页面仍属于各自领域；侧栏是现有对话内容宿主的一种放置方式。

## 资源呈现路由

所有创建资源或把资源移入工作区的动作使用同一套呈现规则。当前区域不是聚合工作区时，在资源的原生区域激活它：文件进入代码工作区，终端打开进入终端工作区，对话或代理进入 AI 工作区。当前区域是聚合工作区时，先创建原生资源，再把引用加入当前组合，并保持聚合工作区不变；当前组合已有四个窗格时，引用放入新的聚合标签。

该规则覆盖首选编辑器/终端打开文件、文件面板新建标签、AI 侧栏对话移回工作区，以及 SSH 与命令历史终端启动。路由完成后，资源激活仍由原生所有者负责。

## 窗格操作与分屏流程

所有区域的窗格右键菜单使用同一顺序：拆分标签、更换窗格位置、放大/还原窗格、将窗格移至新标签、移除窗格。终端窗格随后追加复制/粘贴、运行中命令、SSH 和终端类型操作；只剩一个终端时显示关闭该终端的动作。标签操作菜单也提供同一组公共窗格动作。

更换窗格位置使用共享落点模式：计算覆盖层前先移除正在移动的窗格，`moveWorkspacePane` 再把同一窗格标识插回所选落点。打开覆盖层前会先退出放大，移动后保持该窗格焦点，并通过现有工作区投影持久化终端顺序。

分屏始终是显式落点操作，最多四个窗格。聚合工作区拆分终端时打开共享的拆分资源菜单（未放置的现有资源、新建终端/文件/对话、文件选择器或代理），不再默认创建终端。原生终端分屏仍先选落点并继承聚焦终端类型，终端类型选择器保留为原生终端动作。全局快捷键遵循同一规则：聚合工作区快捷键打开拆分菜单，原生终端快捷键保留继承类型或直接拆分行为。

## 生命周期与历史

切换标签恢复其完整窗格树、焦点和放大状态。在原生工作区选择已有资源会打开或选中其所属容器；聚合工作区的资源切换按钮把资源移入当前组合，已存在时只聚焦。拆分通过显式落点操作完成。拆出和合并保留窗格/资源标识与实际内容宿主；终端 effect 依赖稳定的窗格标识，持久化回调读取当前所有者。

整组变更先完成所有关闭守卫。删除组通过资源协议删除每个成员，再移除分组和历史元数据。删除文档成员只关闭视图，不删除磁盘文件；批量删除对话不会自动创建替代对话；删除代理成员会忘记本地持久会话引用。归档是单独确认的操作，保留原分组与可恢复历史。存储失败通过持久错误通知提供重试、详情和关闭。

终端拆出/合并会将后续历史写入排在所有权迁移之后。数据库事务只移动选中窗格的命令块和聊天。删除混合组中的终端窗格只删除该窗格历史，不连带删除兄弟窗格。合并源会话在迁移成功后才删除。内存聊天使用同一窗格标识迁移；历史引用会找到已迁移窗格当前的所有者。

历史写入同时按活动容器和持久历史标识串行化，覆盖恢复到另一个活动容器的情况。窗格和历史标识使用有界生成值，不再拼接文档路径。关闭、自动保存、归档、删除共享队列。关闭后重试，以及同名活动容器标识被复用时，仍使用捕获的历史身份。删除抑制检查入队时捕获的请求标识；重新打开时清理对应抑制和 writer 缓存。历史快照只保存引用和布局元数据，不包含对话正文或凭据。未保存文档沿用保存/丢弃守卫；引用不可用或草稿已丢弃时明确报告恢复失败。

## 重构审查

| 发现 | 处理 |
| --- | --- |
| 打开文件和移回 AI 对话的跳转目标不一致 | 增加统一呈现规则：原生区域跳转到资源所属工作区，聚合工作区添加引用并保持不切换 |
| 不同区域的窗格菜单不一致，且缺少更换位置动作 | 为终端、代码、AI 和聚合窗格统一动作顺序，并共用窗格移动覆盖层；标签操作菜单提供同一组公共动作 |
| 聚合终端分屏静默继承终端并跳过拆分选择器 | 聚合分屏改为打开共享拆分资源菜单；删除待处理终端分屏路径 |
| 到四个窗格时终端菜单仍提供分屏/类型动作 | 分屏和终端类型动作与其他窗格菜单一样受四窗格上限约束 |
| 资源投影行可能被当作标签 | 移除仅用于投影的标签模型和原生聚合页面变体；内容行全部来自权威容器 |
| 终端、区域、聚合树重复维护操作和几何算法 | 共用泛型树操作、比例更新、几何和窗格画布；只保留存储格式/领域适配 |
| 终端 store 保留无运行调用的分组变更/归档接口 | 删除这些接口和过时语义；分组操作进入公共生命周期服务 |
| 区域和聚合窗格删除绕过公共守卫流程 | 统一调用 `removeContainerPane` |
| 恢复已有容器改变标签栏位置 | 释放其他容器的重复资源引用，同时保留目标标识和位置 |
| 启动协调可能清除尚未加载的布局 | 增加加载/写入屏障，加载完成时重新执行聚合工作区协调 |
| 可见分组排序可能扰动其他区域或归档历史 | 在原有顺序槽位中持久化局部排序，保留隐藏及无关分组 |
| 终端拆出可能丢失历史或重启进程 | 事务化窗格所有权迁移、串行写入、稳定内容宿主和所有者引用 |
| 关闭/删除混合终端成员可能删除兄弟历史 | 增加有界的窗格级删除；没有存活兄弟窗格时才删除所有者 |
| 批量删除对话可能创建多余成员 | 资源协议删除不触发自动后继激活 |
| 全屏输出可能遮住合并落点 | 全屏可见性观察公共放置状态 |
| 损坏的终端布局未经验证进入恢复 | 转换/恢复前增加有界验证 |
| 导航和 AI store 仍暴露独立标签排序 | 删除活动排序接口和资源投影排序；编辑器命令导航读取权威容器顺序 |
| 工具页拖拽未进入公共排序路径 | 工具页标识参与同一持久标签顺序和数字切换，同时保留单例路由 |
| 资源聚焦可能卸载正在控制拖拽的标签栏 | 同一可见逻辑列表接续捕获的手势，直到释放或取消 |
| 进入 AI 侧栏可能注册多余默认对话 | 只挂载明确注册的主区和侧栏资源 |
| 启动激活可能覆盖设置或明确选中的工具页 | 保留这些目标，同时对齐恢复资源的选择 |
| 长路径可能导致窗格或历史标识无效 | 使用有界生成标识，并验证长路径快照往返 |
| 关闭与恢复同一历史记录可能在不同容器队列间竞争 | 按持久历史身份串行化，保留不可变的重试身份 |
| 重试部分完成的分组创建可能产生重复分组 | 重试沿用生成的组标识，数据库创建保持幂等 |
| 合并、克隆和目录更新仍有局部递归遍历 | 改为公共树更新和映射操作 |
| 窗格移出后兄弟窗格仍在原会话，历史可能指向错误所有者 | 恢复前查找窗格当前持久所有者 |
| 真实容器替换开始占位符后，选择可能仍指向已移除容器 | 占位符移除复用公共选择修复路径 |
| 终端原生激活未改变聚焦窗格时，标签栏选择可能停在别的容器 | 除窗格焦点外，单独跟踪原生活动会话标识 |
| 重命名单资源对话标签只改标签文字 | 将重命名交给对话所有者，保持标签与历史标题一致 |
| 分组标题是没有共享拖拽把手的按钮，跨分组拖拽会丢失候选项 | 恢复分组标题的拖拽把手，允许标签/分组跨边界作为落点，并支持拖到未分组尾部时把整组移到末尾 |
| 标签拖到组内成员后可能被同步重新移出分组 | 在权威更新前捕获目标分组，并显式持久化该分组 |
| 聚合工作区资源切换按钮新建第二个标签，而不是扩展现有组合 | 把引用移入当前组合，释放旧放置；已存在时只聚焦 |
| 区域投影仍保留未使用的标签顺序和开始页开关 | 删除第二套顺序状态；标签栏顺序只来自工作区快照 |
| 仍会读取旧区域布局键和旧导航顺序 | 删除两个读取入口；`workspace-containers-v2` 是唯一工作区布局记录 |
| 会话恢复仍解析旧 `shellType` / `ssh` payload | 恢复只接受当前 `{ layout }` payload |
| 历史元数据仍解析旧终端 payload | 历史只读取当前终端窗格树 |
| 窗格迁移和删除仍处理旧版空窗格行 | 两者只按明确窗格标识操作 |
| 原生 `workspace` 标签类型仍保留路由 | 删除路由和过时测试 |
| 停靠布局仍读取 v3-v5 记录并重命名旧条目 | 只读取当前 `dock-layout-v6`；未知版本恢复默认布局 |
| 底层文案仍以中文硬编码在代码中 | 默认标题、上限、空态提示、恢复失败和恢复不完整提示统一接入 i18n 目录 |

保留的适配层只转换当前领域 payload：终端会话 JSON、文档和比较引用、对话或代理引用。它们不是另一套标签、树、分组或关闭实现，也不读取旧数据格式。原生编辑器和代理页面负责注册资源宿主，内容标签行来自权威容器。工具页保留单例路由，并使用公共排序机制。新增工作区行为应放入权威模型/服务/provider，只有进程、内容或存储行为有差异时才增加领域适配。

同时运行了严格模式通用界面扫描。其全仓库 64 项结果需要人工解释：选择器模式把自定义 `Select` 组件视为原生标签，包装按钮通过 props 转交动作，文本域尺寸由共享样式控制，测试夹具也被当作产品界面扫描。标签轨道按设计隐藏原生滚动条，应用另外拥有全局主题滚动条规则。报告没有涉及新增分组或窗格界面。这里如实记录启发式报告，不将其描述为扫描全绿。

## 验证约定

`npm run test:workbench` 对 `vitest.workbench.config.ts` 明确列出的公共底层要求**语句、分支、函数、行四项覆盖率全部 100%**。范围包含泛型树/几何、工作区模型/store/生命周期、资源/历史适配、反馈 store 和公共标签 provider。不使用源码覆盖忽略指令或排除未覆盖代码来达标。这个门禁针对统一底层，不代表无关应用功能或原生代码也有 100% 覆盖率。

单元回归覆盖所有区域、独立布局、异常快照、加载屏障、公共操作、守卫、历史队列、删除抑制、重试、局部排序、原生所有权迁移和进程宿主保留。浏览器回归覆盖四区域的分组创建/改名/成员归属/折叠/颜色/确认/删除、窄宽布局、聚合恢复，以及终端合并/拆出不重启进程。原生测试覆盖事务迁移、兄弟窗格安全删除、分组局部排序和历史元数据验证。
