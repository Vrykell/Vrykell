# 发布签名更新

关于页仅跟随正式版。已有测试版不提供正式更新源；发布签名正式版之后，已安装客户端才能获取更新。更新源不可用时会显示可重试的错误。

验证公钥位于 `src-tauri/tauri.conf.json`。匹配的私钥应保存在仓库之外的受保护存储中，并妥善备份；本机密钥位于当前用户的 `.tauri` 目录。将私钥内容配置为仓库密钥 `TAURI_SIGNING_PRIVATE_KEY`；仅在私钥设有密码时配置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，两者都不能提交到仓库。遗失或更换密钥会使已有客户端无法验证新安装包。

1. 保持 `package.json` 及其锁文件、`src-tauri/Cargo.toml` 及其锁文件、`src-tauri/tauri.conf.json` 的版本一致，使用正式的 `MAJOR.MINOR.PATCH`。
2. 完成要求的检查，将待发布提交合入 `main`。
3. 在 `main` 手动运行 **Release signed updates**，填入匹配的 `vMAJOR.MINOR.PATCH` 标签。先关闭 `publish`，生成可检查的发布草稿。
4. 工作流生成四个已配置桌面目标的签名包，并在允许发布前校验 `latest.json` 的四个平台条目。检查草稿，并在受支持平台试验升级。
5. 将已验证草稿发布为最新正式版，或在同一未变更提交上重新运行工作流并启用 `publish`。工作流不能覆盖已发布版本。

检查和下载不会静默安装。用户确认安装重启、处理未保存文档后，才会关闭终端连接；签名失败时不可安装。安装包构建和真实安装属于另外明确请求的验证步骤，单元与浏览器模拟不能替代真实升级试验。
