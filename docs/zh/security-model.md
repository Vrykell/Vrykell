# 安全模型

空启动窗格在布局元数据中使用经过校验的布尔标记。用户明确恢复历史时，沿用原资源所有者重建空窗格，不恢复命令，也不重建缺失的非空对话内容。远程空窗格要求存在原保存连接，仍经过标准认证路径，不改变凭据、能力或执行策略。

## 会话专属应用工具

内部工具适配层使用带认证的临时回环分帧连接及标准输入／输出辅助进程，令牌仅在子进程环境中传递。每个外部连接独立维护工具白名单、活动轮次和待处理结果标识，初始化及历史重放不能执行工具。只有主窗口能答复 `acp_app_tool_result`，结果受大小限制并关联活动请求。现有工具实现继续经过后端策略、路径授权、系统确认及一次性租约。终端目标明确选择并在轮次内固定，远程目标不能调用本地文件工具。取消会清理审批和问题，迟到的批准不能执行。不暴露凭据、任意应用命令分发、公网监听或新内容来源。边界与测试见 `application-tools.md`。

> 读者：**在 Vrykell 上加任何新功能前先读这一页**，尤其是接入第三方代码（MCP 服务器、技能、外部 harness）和新增 IPC 命令的时候。
> 配套文档：`security-review.md`（历次审查与未决项）、`acp-harness-integration.md`（外部 harness 接入设计）、`architecture.md`（分层）。

## 引用型组合与工具恢复

同一请求中的终端命令在授权与 PTY 写入前按提交顺序串行执行。命令被拒、取消或未确认完成时，后续排队命令不能继续写入；已完成的非零诊断结果不阻塞队列。原有忙碌保护仍防范人工及独立调用方的冲突，取消等待不会终止正在运行的进程。

`save_workspace_history` 只接受有大小限制、版本标识与成员字段白名单的布局引用；拒绝带内容的载荷、非法布局及覆盖终端记录的请求。写入为原子的历史元数据，不是启动进程记录。增量迁移保留现有数据，来源与分屏筛选使用写入时维护的索引标记。`get_conversation` 校验标识，使用绑定参数只查询一条元数据，不加载消息。两条命令均不扩大文件访问、网络来源、能力、CSP 或执行权限。

AI 工具被拒绝后，本轮后续步骤只允许解释或向用户提问，不能继续执行，新的用户请求使用新的恢复范围。系统确认、前台要求与授权租约不变；换解释器或编码不代表获得权限。远程工具上下文在执行时也拒绝访问本地文件系统。工具错误和审批结果留在对话中，历史挂载不能重放通知。终端状态区分忙碌、就绪、交互与未知，安静画面不能作为完成依据。诊断仍不记录命令、输出及凭据。

`ask_user` 是有长度限制的内存交互，不是特权执行或审批。请求绑定会话和调用，可以取消并在十五分钟后超时。回答不会创建授权，待处理回调不持久化。被隐藏的工具控制标记绝不执行。本功能不增加 IPC、文件系统或网络权限。

## 1. 威胁模型：谁能影响什么

| 输入来源 | 信任级别 | 它能碰到什么 |
| --- | --- | --- |
| 用户本人（键盘、面板、设置） | 权威 | 一切（终端就是任意代码执行，这是产品） |
| **模型输出**（本机 agent） | **不可信内容** | 渲染路径（Markdown）、工具参数（受审批与租约约束） |
| **抓取的网页 / 搜索摘要 / 技能文本 / MCP 工具结果** | **不可信内容** | 同上；也是**提示注入**的入口（内容里可以写"请把 X 发到 Y"） |
| **远程 SSH 主机** | **不可信内容** | 终端输出、远端文件名；会话记录会落库并再次渲染 |
| **第三方 harness（ACP，规划中）** | **用户添加的可执行程序** | 它自己的进程权限（拦不住）；经我们声明的能力发起的操作（可拦） |
| **被完全攻陷的渲染进程** | 最坏情况 | 一切 UI 能做的事——**包括往 PTY 里敲命令**（见 §3） |

一句话：我们保护的是「**不可信内容不得变成渲染层或执行层的指令**」，以及「**危险操作必须经过不可伪造的确认**」。我们不假装能保护「渲染进程本身」和「用户自己装的程序」。

## 3. 两条「做不到」，必须写清楚

1. **真隔离不可达**：UI 必须驱动 PTY（终端就是产品），渲染进程一旦失陷就等于用户的任意命令执行，任何 IPC 拆分/把 agent 移出 webview 都改变不了这一点。因此我们的目标是**缩小失陷后的收益**，不是挡住失陷本身。
2. **「调用者身份」这一维现在是空的**：`agent` 与 `UI` 都是同一个 webview 里的 JS，后端无法区分。技术上可行（Tauri 会把调用者 webview 注入命令签名，页面无法伪造），但**只有一个 webview 时做了等于没做**。等引入第二个 webview（例如 ACP harness 的会话 UI）时，同批做：命令命名空间 + 按调用者鉴权 + 租约绑定 `webview_label`。

## 4. 新功能自查清单（每个 PR 都要能回答）

1. **新 IPC 命令**：是否受租约/策略门控？加进受门控命令清单了吗？会不会成为"任意路径读/写/执行"的新入口？
2. **新渲染路径**：是不是又往 DOM 里塞 `innerHTML`？能不能走 Markdown/文本？必须塞 HTML 时过 `sanitizeOutputHtml` 吗？
3. **新内容来源**（第三方文本/文件/接口）：它算不可信内容吗？进渲染层前消毒了吗？会不会诱发一次外链点击？（链接一律走 `Link`，外链默认交系统浏览器）
4. **新能力或新资源**：CSP 需要放宽吗？`assetProtocol` scope 需要扩大吗？能力清单要加吗？——三问都要写进 PR 说明。
5. **新第三方代码**（进程、脚本、插件）：是否由用户显式添加？设置页是否写清"添加即授权"？
6. **新授权**：是否复用现有审批链（等级表 + 形态授权 + 超时 + 危险规则），还是自造了一套？自造的一律需要评审。
7. **日志**：新写日志是否泄漏命令文本/输出/密钥？（诊断日志只记元数据）
8. **测试**：这条防线有没有对应的单测/e2e？（见 §2 最后一列）

## 已保存连接的扩展

独立端口转发新增三个显式生命周期命令：启动仅接受已保存连接和规则的标识符，停止定位同一标识符对，状态仅返回运行元数据。后端重新读取并校验已保存端点，复用现有认证、代理和严格主机密钥检查；渲染层不能传入 shell 文本或凭据参数。默认绑定回环地址；用户选择公开监听地址后，对应网络可以访问端点，因此自动启动保留为每条规则的显式偏好。会话数、客户端数、协议握手与缓冲区均有限制。停止、端点修改、主机删除和退出应用会关闭受管监听。不会扩大 CSP、能力或路径范围，也不新增 HTML 渲染或诊断内容。

代理配置命令校验配置标识符、地址语法、端口范围和凭据大小。非敏感配置以原子方式保存；密码保留在现有平台凭据存储中，不包含在返回对象内。终端辅助进程使用经过校验的配置标识符，不在命令参数中携带凭据。HTTP CONNECT 和 SOCKS5 的协议头、地址和握手时长均受限，目标主机密钥验证保持不变。这些协议不加密初始代理认证交换，请在受保护网络中使用可信代理。

远程环境变量作为会话选项发送，不写入本地进程环境。界面和后端分别校验名称、大小、数量与控制字符。备注是具有字节上限的用户上下文，不是策略或授权；诊断记录脱敏环境变量内容及两种备注。本次不扩大能力权限或 CSP 来源。协议、参数、序列化和数据库往返测试与完整页面编辑测试同步提供。支持组合及限制见 `ssh-profiles.md`。

## 端点迁移与文本操作

现有凭据写入命令可将已配置端点的密钥复制到同一 API 类型、经过校验的 HTTP(S) 端点。优先保留目标端点已有密钥，不向渲染层返回明文。跨来源沿用密钥前，界面必须请求明确确认；取消则保留原端点及密钥。原凭据仍可供其他配置模型使用，自定义服务商元数据不包含密钥。

围栏代码着色通过转义文本元素渲染令牌切片，不注入 HTML；未知语言和超大内容回退纯文本。模态编辑命令复用已有保存、路径选择、版本校验及关闭保护；明确强制关闭不会保存草稿。复制操作仅将用户选中的文本写入现有系统剪贴板通道。不新增原生命令、文件授权、网络来源或能力。

新本地终端读取已登记的系统及用户可执行搜索路径，合并进子进程环境，不改动父进程环境，也不执行脚本获取路径。继承的自定义目录保留优先级，不增加文件访问授权，不改变远程环境。

## 补全与市场请求

新增 `shell_complete` 命令只接受已知 shell 标识、绝对工作目录、受长度限制的普通补全文本与有效光标偏移。内部固定脚本通过环境数据接收输入，启动前拒绝执行语法；查询不进入活动终端。子进程时长及输出受限、标准输入关闭、窗口隐藏，丢弃请求时终止子进程。远端面板不会查询本地 shell。这条只读发现路径不增加文件写入授权、能力或 CSP 例外，补全文本仍在诊断中脱敏。

现有市场命令现遵循系统代理，保持端点白名单、重定向约束与证书校验。索引与描述正文受大小限制，描述请求采用受限并发与总截止时间；列表读取固定到索引版本，切换仓库使旧界面响应失效。安装的外部技能仍默认未信任。共享资源切换入口引用原有领域身份与关闭保护路径，不重建活动资源，也不改变授权。
