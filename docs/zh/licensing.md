# 许可与再分发

## 项目范围

除另有说明外，原创代码和文档采用 Apache-2.0。版权声明为 `Copyright 2026 Vrykell contributors`。完整协议位于根目录 `LICENSE`，项目范围和第三方例外见 `NOTICE`。

外部代码、字体、图标及其他材料保留各自许可证。将其纳入项目不代表版权转移，也不授予外部商标权。保留原始声明及其原文，不翻译替换许可证正文。

## 生成与验证声明

安装锁定的前端依赖，并确保原生包管理器可用后，运行：

```sh
npm run licenses:generate
npm run licenses:check
npm run build
```

生成器检查前端输出模块、导入的图标集合、内置字体来源，以及 `x86_64-pc-windows-msvc`、`aarch64-apple-darwin` 和 `x86_64-unknown-linux-gnu` 三个参考目标的原生依赖。解析原生元数据时可能下载尚未缓存的锁定包，不会构建安装包或修改锁文件。

生成文件为 `public/legal/THIRD_PARTY_NOTICES.txt`，包含组件版本、许可表达式、源码位置及原始许可／声明正文。原生清单采用保守范围，包含构建依赖；列入清单不表示每个目标都链接所有条目。已发布包缺少的许可正文保存在 `licenses/third-party/`，能够定位时同时记录上游来源。

依赖、导入资源、内置字体、原生特性或目标发生变化时，重新生成并提交声明。缺少元数据、许可正文或生成结果过期时，验证失败。新增手工补充项必须对照实际上游版本，保留原始版权声明。

## 源码可获取性

生成清单链接到精确版本的原生源码归档。受许可约束的源码，包括未修改的 MPL-2.0 代码，在对应位置按原条款提供。再分发可执行文件时，保留这些源码链接及相应许可正文。若修改受约束文件，应按对应条款提供修改后的源码，并更新声明指向该源码。项目整体协议不覆盖文件级源码义务。

内置字体继续采用 OFL-1.1。保留原始版权、许可信息、保留字体名称声明及转换来源。格式转换必须保留原始字体数据和等价元数据，才能按仅压缩转换处理；其他变化需要单独核对许可。

## 二进制分发

打包配置将根目录 `LICENSE`、`NOTICE`、生成的第三方清单及五份字体许可证放入安装后的 `legal` 资源目录。第三方清单也随前端资源分发。安装程序的许可字段指向根许可证，包元数据声明 Apache-2.0。

发布安装包前，检查实际原生载荷，包括自包含安装包复制的系统运行库。补齐其原始声明，以及适用的源码或重新链接信息。生成的源码级清单不代表尚未构建的平台安装包已经完成核验。新增架构或启用特性后也应重新生成。

即使压缩过程移除了注释，仍需保留逐组件声明。项目许可证不转授应用名称或外部标记的商标权，集成说明也不代表获得背书。
