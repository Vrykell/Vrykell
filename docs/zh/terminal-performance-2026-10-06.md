# 终端性能验证（2026-10-06）

本轮针对历史输出增多后的卡顿，以及开启详细日志时的输入延迟。终端解析、光标与交互仍由现有 xterm 管线处理。

## 已定位的额外开销

- 普通终端每次解析输出后提取带样式的 HTML，随后更新 React 状态；即使屏幕由终端自己绘制，也发生这项开销。
- 块状态更新时，为所有历史块创建新的投影对象，导致已完成块重新渲染。
- 历史输出离开可见区域后仍参与布局与绘制。
- 开启日志后，每个输入相关事件独立调用 IPC；后端每条记录重新打开文件、检查文件大小并写盘。

## 实现

- 历史块投影保留未变化对象与数组的引用，块组件和输出组件使用记忆化渲染。
- 2026-10-09 更新：历史输出通过布局、样式和绘制隔离保留真实换行高度。移除估算 `content-visibility` 高度，避免输出进入视口时改变历史几何；贴底在绘制前完成，内容与复制保持完整。约 3 万行的 WebKit 回归测得输入 P95 为 143ms、追加延迟为 345ms。
- 普通本地终端不再生成连接页面快照。SSH 仅在认证提示、认证拒绝或连接结束/失败时生成带样式快照；普通交互更新不提取 HTML。
- 前端日志保留每条结构化记录，以最多 64 条或 50ms 的窗口批量发送，导出及修改自动保存设置前提交待发送记录。
- Rust 日志由后台线程复用缓冲文件句柄，按最多 64 条或 50ms 写盘；导出、切换自动保存设置与正常退出时显式冲刷。轮转与脱敏规则保持原有行为。强制终止进程仍可能丢失最后一小段待写记录。
- 输入发生后，下一批 PTY 输出优先发送，避免继续等待通常的 16ms 输出聚合窗口；连续输出仍按原有窗口和字节阈值合批。

## 本机对比

使用 Playwright、开发构建与 Tauri mock，经过真实 React 和终端前端管线。历史场景载入 200 个命令块，每块 150 行带样式输出，共约 3 万行。每项是单次测量，不代表网络或真实桌面环境的端到端延迟。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 历史载入至两个动画帧后 | 1028.8ms | 634.8ms |
| 新命令输出可见等待 | 1141ms | 186ms |
| 输入编辑器按键至下一帧，样本中的 P95 | 72ms | 50ms |
| 追加命令后滚动内容高度 | 489481px | 489481px |

另一个场景开启自动保存日志，向经典终端连续发送 2 万行输出，同时通过终端输入 API 发送 12 个按键；全部按键到达 PTY mock，输出也进入终端缓冲区，本次测量最长帧等待 53.3ms。它验证前端调度与日志路径，不测 SSH 网络往返。

现有测试机日志最近 4000 条记录中，212 次 `pty_write` 完成耗时中位数 2.3ms、P95 11.4ms、最大 26.6ms。这是优化前已有记录中的 IPC 写入耗时，并非按键回显或优化后对比结果。

## 回归入口

- `e2e/terminal-performance.spec.ts`：3 万行历史、输入、新输出、返回历史查看；2 万行连续输出与开启日志后的按键传递。
- `e2e/follow-bottom.spec.ts` 与 `e2e/block-width.spec.ts`：贴底、阅读位置、字号与运行/完成宽度。
- `e2e/ssh-auth.spec.ts`：认证提示、取消信任、主机密钥变化、断开与远端块输出。
- `src/features/terminal/model/__tests__/blockProjection.test.ts`：引用复用、折叠状态、变更失效。
- `src/features/terminal/model/terminalFrame.test.ts`：认证与普通交互快照复用。
- `src/platform/diagnostics.test.ts` 与 Rust diagnostics 测试：批量传送顺序、定时提交、错误、脱敏、记录完整性与文件轮转。
- Rust PTY 测试：输入回显优先发送、持续输出仍然合批。
