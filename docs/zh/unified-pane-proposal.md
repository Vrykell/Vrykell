# 统一工作区方案

状态：已作为左侧栏目的地实现。共用标签栏引用现有终端、文档、比较、内置对话及外部会话。全部工作区下拉菜单在其他工作区仍只切换资源；在聚合区内，它把所选资源加入当前组合，不作为从其他工作区进入聚合区的入口。最多四个混合窗格共用仅引用资源的布局。现有标签模型和存储继续负责激活、重排、保存、进程归属及关闭保护，移动挂载宿主不会重建资源。

## 结论

将终端、对话和文档窗格放入同一工作区是可行的。现有共享标签栏、拖动交互、命令草稿引用和可停靠对话已提供基础。应统一展示与位置，而不是把三者的会话数据强行合并：它们的生命周期和安全边界不同。这是中等规模的架构调整，不是简单改一下布局。

## 现有约束

- `src/features/workspace/model/windowLayout.ts` 保存的是终端专用分屏树。叶节点携带本地或远程终端配置；最小宽度、拖放位置和恢复逻辑都依赖终端叶节点。
- `src/app/layout/WorkspaceShell.tsx` 组合稳定的领域宿主。切换导航时，编辑器、终端与对话各自保留挂载状态，仅改变可见性。
- `src/features/chat/stores/aiWorkspace.ts` 独立管理对话标签和持久化会话。关闭标签不等于删除历史会话。
- 文档需要未保存关闭保护和版本校验保存；终端拥有进程、输出解析器与尺寸驱动；对话拥有流、待处理授权、执行终端引用及草稿。移动视图不能重建这些资源。

## 当前结构

资源身份与排布分开。现有工作区标签、文件键、对话 ID 和外部连接 ID 继续作为权威来源。共用标签栏只投影这些引用，并委托原所有者切换与执行受保护关闭，不引入第二套实时标签注册表。布局叶子仅记录稳定窗格 ID 与现有资源引用，共享分屏层负责几何、落点及尺寸调整。领域适配器保留原进程、流、文档及草稿的生命周期。

同一文档若允许多个视图，必须共享文档模型；终端和流式对话即使改变位置也只能有一个实际运行实例。隐藏窗格不得保留键盘焦点或接收全局快捷键。

## 分阶段实施

1. 先明确导航与关闭语义。首先统一顶层标签展示，不改变资源身份，也不迁移现有数据。
2. 在现有终端布局旁抽取带版本的通用分屏容器。从一个终端和一个文档开始，保留原渲染器与尺寸同步路径。
3. 通过适配器加入原生及外部对话，覆盖流的归属、待处理审批、输入草稿及明确的执行终端绑定。焦点和关闭保护稳定后，再加入拖动分屏及窗格内标签。
4. 对已保存布局做带校验、回退和回滚的迁移。历史会话、文件访问授权与布局恢复相互独立。恢复测试通过前，新工作区保持可选启用。

## 验收门槛

- 移动、分屏和切换不重启进程、流或文档模型。
- 窗格及窗口关闭都支持保存、放弃和取消，写入失败保留草稿。
- 窄窗口执行各领域的最小尺寸限制，工具栏不折行，隐藏窗格不抢焦点。
- 本地和远程终端保留独立目录、凭据与命令上下文。其他窗格获得焦点时，对话不能自动更换执行目标。
- 恢复能够处理文件被移除、远程主机不可用、会话不存在及旧布局版本，不丢失可恢复数据。
- 用单元和浏览器测试覆盖混合布局、调整尺寸、拖动取消、键盘导航、未保存文件、运行中的流及重启恢复，再替换现有工作区。

## 已交付边界

聚合容器与终端工作区共用平面渲染器、窗格表面、分隔线、落点几何及悬停选择器。分屏动作先选择已有资源或新建终端、文档、对话及外部会话，再沿用现有落点交互；取消不会创建资源。编辑器与外部会话工作区提供同一分屏入口，外部会话使用独立所有者，停靠侧栏改用不同的侧栏图标。焦点资源工具加入标签栏右侧工具条，不新增额外工具条或窗格标题栏。独立的聚合开始页沿用现有启动页结构与控件。最多显示四个窗格，新建、关闭与数字选择快捷键跟随共用标签栏。每个内置对话保留独立阅读区和输入区，可用宽度不足时横向分屏自动改为上下排列。

第一版布局偏好只保存引用、顺序、焦点和比例。恢复时校验树结构，拒绝重复资源及过深／过多窗格，限制比例，并在打开聚合工作区时移除不可用引用。布局元数据不会重新打开任意文件、授予访问权限或重建资源。领域历史和恢复机制保持独立；缺失资源回退至可用标签，文档仍保留原有未保存关闭保护。

窗格内标签组及拖动分屏属于后续可选扩展，不影响本次交付的共用标签栏与混合分屏。原有各领域工作区继续保留。单测及浏览器场景覆盖身份稳定、恢复校验、混合资源、独立草稿、调整尺寸、窄窗口和外部会话关闭保护。
