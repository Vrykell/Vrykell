# Vrykell Feature Spec and Test Checklist

> Last updated: 2026-10-28

Appearance and toolbar regression checklist:

- Shell opening modes use the shared segmented control for classic and block mode. Click and arrow-key choices persist per profile; profiles without block integration offer only classic mode. Verify dark/light themes, narrow layouts and selection persistence.

- Tool permission rows use the shared segmented control for allow, ask and deny, preserving saved levels and existing authorization rules. Wide settings show two items per row; narrow settings use one column. Verify keyboard switching, search focus, navigation persistence and narrow layouts.

- Model lists sort names within each group and show only supported capabilities as colored icon pills: green vision, violet reasoning, orange tools and blue search, each with a faint matching background. Per-model settings place four selectable capability pills below the other options and persist explicit choices; the bottom-left Reset action restores detected capabilities without changing other options. Changing the provider or model ID detects them again. Verify filtering, reset, reload, dark/light colors and narrow layouts.
- Shared sliding controls use distinct track/thumb/text colors, 14 px label insets and compact height. Thumb placement tracks both axes after wrapping and font loading. Verify both themes, larger fonts, keyboard selection and host authentication/view controls.
- All four workspace strips use the same 32 px action targets and 18 px icons as the terminal. The leading resource menu uses a downward chevron with a 4 px first-tab gap. Verify projected tools, dropdown hit bounds and tab corners.
- Host-card connection addresses use the page font, retaining literal `@` and single-line truncation. Browser coverage compares card-title/address typography.
- Additional light palettes use stronger surface separation, borders and ink independently of the dark ratios. Main text reaches 7:1 and terminal palette text reaches 4.5:1 against its background. Original defaults remain available.

## Bundled typography

- Interface copy, buttons, menus and chat use a selectable local variable sans face. Two interface families and three monospaced families are bundled. Terminal input, output, history, editor text and previews default to a local monospaced face with Chinese, Latin, box-drawing and prompt-symbol coverage. Default regular and bold faces are included; alternatives support variable weights.
- Default faces finish loading before application mount and renderer measurements. Failed local loads retain system fallback and a usable application. Existing saved font preferences remain compatible; installation-dependent choices fall back to the bundled face.
- Font binaries together stay below 30,000,000 bytes. Preserve upstream licenses and source/checksum metadata in the distributed font directory. No external font requests or expanded resource permissions are required.
- Interface, terminal and editor font controls live on the font and display page. Interface choices also include all available monospaced families. Font lists use plain family names and hide non-bundled faces unless explicit local-face probes succeed. Each list also offers an explicit system default using native interface or monospace font selection. Editor behavior preferences remain on their own page. Keep interface family/size and editor family/size/weight/spacing independently persisted, with immediate previews and reset behavior.
- Verify local face loading without installed fonts, mixed Chinese/Latin cell widths, prompt symbols, unavailable-family filtering, independent interface/editor settings, moved search destinations, keyboard dropdown dismissal, narrow/wide layouts, failed-load recovery and production resource inclusion.

## Tool recovery and transfer naming

- Profile, server and agent choices use real secondary menus; a sole wrapper is flattened. Directory selection keeps the menu open. File splits support opening existing files, with no resource created before placement. File and agent panes share a right-click removal action; removing placement preserves owners and the last pane cannot be removed. Cover keyboard menus, narrow viewport bounds, deferred file opening and right-click removal without extra tool rows.

- In-transcript user questions support options, free text, skip, cancellation and a deadline. They resolve only the owning conversation/call, never grant permissions and never reactivate from history. Cover request, card and browser continuation.
- Leaked tool syntax is hidden from answers, copying and assistant context replay, including spaced and partial streaming markers. It is never executed. Ordinary code examples remain intact.
- Creation pickers retain their trigger snapshot across parent-menu removal and flip toward available viewport space. Agent startup accepts a project directory. Cover narrow and wide menus, keyboard selection and explicit directories.
- Split actions stay in the current workspace. Editor and conversation splits reuse the same pane store factory, content host, geometry, placement controls and dividers as mixed compositions. Single panes hide removal. Toolbar action containers reserve their intrinsic width. Resource icons resolve actual profiles. A composition uses its first pane's content icon and a small circular count badge at the top right; a single pane has no badge.

- AI tool and reply failures stay inline with output, details and retry; reloading history never republishes notifications. Approval timeout has no toast. Cover live/remounted cards, restored browser history and ordinary notifications.
- Tool denial ends all tools for the current turn, including questions, followed by one explanation. At most one user question opens per turn; retain only the selected option or typed answer as inset plain text and reject repeated confirmations. Nonzero exits and busy snapshots remain diagnosable. Captured remote contexts cannot execute local filesystem tools. Cover structured denial detection, question repetition, remote gate rejection and terminal readiness.
- Concurrent command calls to one captured terminal execute in order. Denial, cancellation or unconfirmed completion blocks queued writes; a completed diagnostic failure permits the next command. Cover deferred execution, aborted queues, independent turns and the real model-stream restricted handoff.
- Uploads and downloads preserve original names when available; numbering applies only to actual collisions. Explicit duplication retains always-numbered semantics. Native tests cover free names, repeated collisions, extensions, hidden and Unicode names; browser tests cover single drops.

## Editor and toolbar refinements

- Shared editor preferences contain optional line numbers, wrapping, modal bindings and independently persisted typeface, size, weight and line spacing. Local and remote file-opening pages retain only target-specific choices. Opening lines with `o`/`O` and numeric jumps through `:N`/`NG` operate on the real buffer. The find strip has equal corners and a vertically centered close control. Verify with editor-interface-details and file-location-shortcuts browser cases plus configuration and editor unit tests.
- While modal bindings are enabled, native composition input writes directly to the buffer only in insert or replace mode. Normal, visual and command modes replay committed text as keys, so commands such as `:w` work and unmapped CJK text never inserts; returning to insert mode never replays a cancelled preedit. Verify with the composition-guard and key-replay unit tests and the notepad-editor browser case.
- Tab menus occupy a separate fixed slot beside the scroll track, with a compact eight-pixel corner gutter. Navigation and editing precede opening and creation; creation stays at the far right and a plus never means opening an existing file. Extremely narrow global search hides its shortcut and label without losing its accessible name. Verify scroll boundaries, ordering, search overflow and narrow/wide geometry in editor-interface-details.
- Custom provider creation activates its model; choosing a provider updates the chat model rather than only the configuration view. Preserve endpoint-key isolation. Persistent errors and transient messages share one notification card; technical details and retry remain available. Cover selection with custom-provider unit tests and interface-refinements browser cases.

## File locations and shortcuts

- Restore only the last local directory or drive view and the last directory of each remote connection across launches. Do not restore forward/back navigation trails.
- Directory menus and shortcut settings expose the same two synchronization actions, retaining their existing readiness and directory validation.
- Explicit Tab completion reads the current terminal's local or remote file channel independently of predictive suggestions, without running a command. Relative, home, quoted and drive paths are supported; directory commands include only directories. Tab and Shift+Tab cycle candidates, Escape restores the typed prefix, and late results never overwrite a newer draft or terminal context.
- A dedicated editor preferences page exposes the shared persistent modal-binding switch; the editor action menu and settings search retain the same destination.
- Evidence: path memory, directory shortcut, path completion service/hook and editor preference unit tests; file-location-shortcuts and notepad-editor browser tests.
