# Security Review

> Summary of successive security reviews of Vrykell (last updated 2026-10-16). Scope: backend Rust (Tauri commands, PTY, SSH/SFTP, SQLite, AI HTTP client, web scraping), frontend React (IPC calls, Markdown/HTML rendering, secret and configuration handling), agent tool authorization.
> Companion: **`security-model.md`** — the threat model, the seven defences and the new-feature checklist; read it before adding features.
> Threat model: a local desktop application with no remote server; the main risk surfaces are "malicious remote endpoints (SSH/SFTP/AI/web content)", "malicious file names/paths", "secrets written to disk in plaintext", "command injection", and "intranet probing driven by LLM prompt injection (SSRF)".

---

## Fixed Security Issues

| Issue | Severity | Fix |
|---|---|---|
| `fs_rename`'s `new_name` could contain `/`/`..`, allowing a file to be moved out of its parent directory | High | Validated as a single path component |
| The SFTP directory download `download_dir_recursive` did not validate remote entry names; `..`/separator-containing names could path-traverse and escape the download directory | High | Reject names that are `.`/`..`/contain `/` `\` |
| SSH defaulted to `root` login when the username was empty | High | Changed to erroring with "Username must not be empty" |
| `which_cmd_sync` command probing injection | High | Retained a whitelist (alphanumeric + `-._+`) and switched to `/bin/sh` |
| AI API key written in plaintext to `~/.vrykell/config.json` with permissions not tightened | Medium | Keys moved out of `config.json` into the platform secret store alongside the SSH passwords (DPAPI-sealed on Windows, the system keychain on macOS, a 0600 file elsewhere); with no plaintext migration the runtime reads only decryptable sealed values (unsealed or tampered values count as missing; entering the value again seals it), and directory 0700 / file 0600 stays as defence in depth |
| `ai_stream` had no timeout (a hung network waits indefinitely) | Medium | Added `connect_timeout(15s)` + overall `timeout(180s)` |
| SSE multibyte characters truncated across chunks produced garbled text (not security, robustness) | Low | Byte buffering splits complete lines on `\n` before decoding |
| Wrong migration order caused a startup panic (`no such column: group_id`) | High (availability) | Index creation moved after the ALTER |
| **DNS alternating answers (rebinding) could bypass SSRF validation** | High | `PinnedResolver`: resolve once → validate → cache (TTL 60s), the connection reuses the validated result; an attacker cannot inject an intranet IP after validation |
| **IPv4-mapped IPv6 (`::ffff:127.0.0.1`) bypassed intranet blocking** | High | `is_private_ip` recursively judges mapped addresses by IPv4 semantics |
| **Proxy false positives/bypass**: proxy users were falsely blocked by local DNS; validation was skipped when NO_PROXY contained IP/CIDR entries; local resolution with socks5 was skipped | Medium | `proxy_does_remote_dns_for`: only remote-resolving proxies (http/https/socks4a/socks5h) skip DNS-level validation; validation is conservatively retained when NO_PROXY has IP/CIDR entries; socks4/socks5 are always validated |
| **Proxy not taking effect**: reqwest does not read environment-variable proxies by default | Medium | `env_system_proxy` builds Proxy::custom (HTTPS_PROXY/HTTP_PROXY/ALL_PROXY/NO_PROXY) |
| **Unbounded response body reads (memory DoS)**: web_fetch/crawl/search/registry/skills read the whole body via `text()/bytes()` | Medium | `read_body_capped` streams and truncates (web 10MB, SKILL.md 1MB, install files 2MB) |
| **Unchecked fetch redirects with no host restriction** (the skill marketplace's first hop was hardcoded, redirects could escape) | Medium | `is_github_host` whitelist; both the first hop and redirects are restricted to GitHub domains |
| **zip bomb: the size limit used values declared in the zip header (which can be falsified)** | Medium | Streaming decompression counts the bytes actually written and aborts when the limit is exceeded |
| **Concurrent writes to known_hosts overwrote each other** | Medium | The `verify_host_key` read-modify-write is serialized inside a process-level Mutex |
| **WebView had no CSP + the asset protocol scope was wide open (`$HOME/**`)** | High | Set CSP (script only self/inline, connect only ipc, img no remote sources, object/frame fully disabled); asset scope narrowed to `$APPDATA/**`, and wallpaper files are dynamically authorized via `allow_file` by the Rust side according to the user's selection |
| **markdown remote image exfiltration/tracking surface** | Low | Images are degraded to link text (remote images are not loaded), together with img-src having no remote sources |
| **The agent file tool could read secrets and leak them to the LLM (prompt injection)** | High | `sensitivePathReason` heuristic (.ssh/.aws/.env/config.json, etc.) → forces a per-invocation prompt regardless of the permission mode |
| **SSH hostname parameter injection (`-oProxyCommand`, etc.)** | Medium | `validate_ssh_host`: reject hosts starting with `-` / containing whitespace |
| **The SSH remote injection script could be tampered with → arbitrary code on the remote** | High | The injection script is a static constant inside the binary (not written to disk, not concatenated with remote data) and is passed as base64; `umask 077 + mktemp` creates a 0600 temporary file to prevent symlinks; tamper-resistance in transit relies on SSH encryption + OpenSSH host key TOFU confirmation; the fallback `exec "${SHELL:-sh}" -i` is quoted to prevent word splitting (a malicious `$SHELL` can only fail to connect, never execute); on injection failure it silently falls back to classic mode |
| **SSH passwords stored in plaintext in SQLite** | High | Passwords moved into the secret store (`secret.rs`: macOS Keychain / platform fallback 0600 file), leaving only a redacted marker in the database; plaintext in legacy databases is migrated automatically |
| **SSH first connection TOFU had no user confirmation** | High | The backend no longer records automatically: when unrecorded it returns `HOST_KEY_UNKNOWN:<fingerprint>`; the frontend form pops up a fingerprint confirmation, and only when the user chooses "Trust and continue" is known_hosts written (`ssh_trust_host_key`) |
| **`HistoryDb::open().expect()` startup panic** | Medium | On open failure it degrades to an in-memory database (history unavailable, the application keeps running) |
| **Migrations swallowed ALTER errors and hoped for the best** | Medium | `PRAGMA user_version` versioning + `ensure_column` per-column checks, so real migration failures report an error |
| Skill marketplace GitHub URL parsing (misjudging `/tree/main` and `.git` suffixes) | Low | Switched to standard parsing with the `url` crate, taking only owner/repo |
| **Agent tool authorization was decided in the webview**: one tool path that forgot to ask could read secrets or write files | High | The decision moved into Rust (`agent/permissions.rs`): the level table, the danger/credential/durable heuristics and **single-use leases bound to the command plus an argument digest**; the gated commands (`read_file_text`/`write_file_text`/`edit_file_text`/`fs_search`) fail closed without one |
| **A dangerous-command confirmation could be answered by page content** (prompt injection) | High | A hit now goes through a **native system dialog** that page content cannot answer; both the dialog and the approval card have a deadline and deny when it passes |
| **A local pane on the default "system" shell was judged by POSIX rules on Windows**: dangerous commands such as `Remove-Item -Force` raised no confirmation | High | An unknown or default shell is judged by platform family (Windows → the Windows table); the same batch fixed "only the last command block of one submission came back" |
| **Wrappers hid commands** (`cmd /c`, `powershell -c`, `env …`, `sudo …`): position-anchored danger rules never saw what was inside | High | Wrapper prefixes are normalized to line boundaries before judging, and credential paths accept both `/` and `\` separators |
| **Durable writes were not asked about** (rewriting memory, creating a subagent, arming or toggling a scheduled task) | Medium | Added `durable.*` reasons; those four writes follow the approval level |
| **Tool output could be read as instructions** (prompt injection) | Medium | The system prompt now states that tool output is data rather than instructions and that credentials stay on the machine, alongside the danger/credential heuristics |
| **An approval card nobody answered held the turn forever** (scheduled runs, locked screen; the former global send slot also blocked other conversations) | Medium | The card denies itself at its deadline (five minutes by default, 1–30 minutes in the settings) and says why, so the turn finishes; native confirmation is clamped to 30s–30min and remains available when the application is unfocused; unanswered dialogs deny with `policy.confirm_timeout`, and late answers cannot issue a lease. Conversations now run independently. |
| **Approval scope was too coarse**: a card could allow one call or the whole tool, and the whole tool is a wide promise for a command runner | Medium | Added a **per-shape session approval**: the program plus its first non-switch word (`npm run`, `git status`), covering that kind of command only and only this session; shells and interpreter launchers get no shape; danger and credential rules decide before a grant is consulted, so a shape can never carry a call past them; "clear session grants" drops them too |
| **Remote rename/create accepted multi-component names** (`..` or separators could place files outside the target directory) | Medium | `platform::path::is_safe_component`: `ssh_rename`, `ssh_create_file` and `ssh_create_dir` now reject `.`, `..` and names containing `/` or `\`, matching the local guard (the download path was hardened earlier; this closes the command side) |
| **Fallback secret file written before tightening permissions** (a brief wide-permission window right after creation) | Low | The non-macOS fallback now creates the file with 0600 upfront and tightens `.vrykell` to 0700, keeping the post-write 0600 fix-up for existing files; macOS uses the keychain and is unaffected |

No high-severity XSS was found in the frontend: AI output is rendered through `react-markdown` (with `rehype-raw` not enabled), so raw HTML is escaped; the `dangerouslySetInnerHTML` in `BlockOutput` is used only to render HTML snapshots **generated by this application itself from the xterm buffer** (all cell text goes through `escapeHtml`), not external input.

## Still Unresolved (Requires Separate Evaluation, Higher Risk/Change)

| Issue | Severity | Description and Recommendation |
|---|---|---|
| In direct-connection mode, DNS pinning re-resolves after the TTL (300s) expires | Low (residual window) | Re-resolution on expiry validates again, so alternating answers can only cause "brief unavailability" rather than penetration. |
| In proxy mode, hostname intranet protection is delegated to the proxy | Low (by design) | Remote-resolving proxies take over domain resolution, which cannot be validated locally; this assumes trust in the user's own proxy. Literal private-network IPs are always blocked. |
| script-src contains 'unsafe-inline' | Low (dev compatibility) | Dev-mode Vite React refresh requires inline scripts; if dev support were dropped, it could be tightened to 'self' only. |
| **A link in third-party content takes the whole app window with it** | Medium | Measured (e2e probe, 2026-10-14): `[click](https://…)` in a reply renders as a plain `<a>` (no `target`/`rel`, no click interception, and no navigation guard on the Rust side); clicking it moved the page url from the app's address to `https://example.com/hooked` and the app UI disappeared. Sources that can carry such a link: an LLM reply, a fetched page's text, a skill, an MCP result — one click turns the app window into an arbitrary page (phishing and UI-hijack surface). The same probe confirmed that `file://` and `ms-msdt:` style schemes are cleared by react-markdown's default URL filter (`href=""`), so only http(s)/mailto really navigate. **Suggested fix (≈0.5 person-day)**: intercept the `a` component — http/https go to the system browser (opener's `open-url`), everything else is refused with a message — plus a navigation guard in Rust that only allows the app's own origin. Regression: an e2e asserting the app url does not change and the system open was called. |
| **The SSH screen snapshot lacks the sanitizing layer the command blocks have** | Low (consistency gap) | `TerminalPanel` renders `frame.html` through `dangerouslySetInnerHTML` without `sanitizeOutputHtml` (the command-block snapshot in `BlockOutput` goes through it). That HTML currently only comes from the app's own snapshot generator (text escaped, fixed `<br>`), so it is safe as it stands; what is missing is the second line of defence under the existing "local DB tampered with" threat model. **Suggested fix (≈0.25 person-day)**: run it through `sanitizeOutputHtml` before rendering, plus a unit test that a `frame.html` carrying `<script>`/`onerror` comes out stripped. |
| ~~**Arbitrary path reads**: `import_attachment` inlined any UTF-8 text file up to 100KB and `read_image_data_url` turned any file up to 20MB into a data URL, neither gated~~ **Fixed (2026-10-14)** | Medium | Read commands now only accept a path an **operating-system gesture** produced: a grant registry in Rust (`files/grants.rs`, persisted to `~/.vrykell/approved-paths.json`, stale entries pruned at startup); pickers run through our `pick_path`, because only Rust opening the dialog knows the choice came from the user; drops are recorded from `WindowEvent::DragDrop` and cannot be forged by the page; the app's own directories (attachments, skills) need no gesture; the unused `read_image_data_url` was deleted together with its implementation and tests. Cargo tests cover granted file, granted directory subtree, app-owned directory, and everything else being refused. |
| **The renderer is still inside the trust boundary** | Medium (by design; cost assessed 2026-10-14) | The agent and the UI share one webview: the four lease-gated commands are only called by agent tools, but the authorization commands themselves are reachable from the page, so an allow-level tool can hand out a lease. The lease mechanism therefore prevents **tool misuse**, not **a compromised renderer**. **Why real isolation is not attempted**: the UI must drive the PTY (the terminal is the product), so a compromised renderer already means arbitrary command execution as the user, and no IPC split changes that; on top of it, two arbitrary-read paths that have nothing to do with the agent surface were found while assessing this (`import_attachment` inlines any text file up to 100KB, `read_image_data_url` turns any file up to 20MB into a data URL, neither gated), so splitting the agent surface buys no isolation. **What is worth doing, in value order**: ① one agent-only entry point with a single lease check (1.5–2 person-days; prevents tool misuse, not a compromised renderer); ② require an OS-level user gesture for arbitrary-path reads — the native dialog and drag-drop paths are recorded in Rust, and the renderer may only read what was granted (1–2 person-days; today's callers already come from those gestures, so the interaction does not change, and it genuinely shrinks silent exfiltration); ③ capability-based file access for the whole panel (3–6 weeks, changes product semantics, still does not stop the PTY — **not doing it**); ④ moving the agent out of the webview (Rust rewrite 2–4 months / Node sidecar 2–4 weeks plus runtime and packaging cost, still does not stop the PTY — **not doing it**). Stated at the top of `agent/permissions.rs` as well. |

## Conclusion

This application is a local desktop tool with a limited attack surface that has been systematically hardened: SSRF (DNS pinning + proxy awareness + mapped IPv6 + response body limits + redirect whitelist), SSH (TOFU confirmation + password Keychain + known_hosts lock + parameter injection + single-component file names), WebView (CSP + narrowed asset scope + zero remote resources), Agent authorization (backend decisions + single-use leases + native confirmation for dangerous commands + mandatory prompts for credential paths + per-shape session approvals + unanswered approvals denying themselves). There are currently no high-priority outstanding items; the one hardening that was evaluated and not done is splitting the IPC surface per audience, for the reason in the table above.
