# Connection profiles

Host management and resource monitoring share one host workspace. List and card views preserve their layout preference; the resource-usage switch enables collection only while this workspace is active. Favorites, tags and folder filters compose independently. Favorites use filled yellow stars in every view. Creating or editing a saved host opens a full page with a persistent save header and a backgroundless favorite button. Section headings sit outside compact row cards; environment variables and notes have separate sections, and optional forwarding and connection behavior sit under advanced options. Test and delete actions follow the form content. Blank ports default to 22 and blank names use the destination. Choose an existing group or enter a new one; choose existing tags or create tags with stable colored dots. Grouping by tags can show one host in several groups. Host and group dragging are intentionally unavailable.

Filters and folder chips scroll with the host results. Expanded tag choices occupy layout space instead of covering controls below; empty tag filters are disabled. The editor uses shared field styling, a four-mode authentication selector and colored removable tag pills. Environment variables start with one optional blank row; removing all rows leaves no stray separator above the add action.

Host rows have no separator borders and retain the shared compact row height. Folder filters use 32-pixel controls; other toolbar actions use the shared compact density. Visual regression checks both themes at normal and 125-percent display scaling rather than comparing unscaled screenshots only.

Host list rows never wrap; narrow layouts truncate or omit secondary metadata. Cards use a compact footprint and a neutral selected background. Resource errors expose shared diagnostic details with retry, and the metrics menu stays within the viewport.

## Port forwarding

The separate forwarding workspace groups named local, remote and dynamic rules by saved host. Editing uses the shared fields and three-way type selector. Rules persist with their host; importing older forwarding strings preserves their endpoints and startup preference. Starting an imported rule migrates it before opening an independent listener, avoiding duplicate terminal-client listeners on later connections.

Start and stop control real authenticated forwarding sessions, not terminal tabs. Local rules connect a device listener through the server; remote rules connect a server listener to this device. Dynamic rules accept bounded unauthenticated SOCKS5 TCP negotiation. Listeners bind to loopback by default; choosing a public bind address exposes that listener to the corresponding network. Each active rule permits at most 64 concurrent clients, and the application permits at most 32 active rules. Buffers and handshake durations are bounded.

The existing saved credentials, temporary authentication cache, host-key verification and proxy path are reused. Standard jump routes support file browsing, resource monitoring and managed forwarding. A startup preference starts a managed rule after its terminal connection is ready. Managed forwards remain active independently until explicitly stopped, their host or endpoints change, the rule or host is deleted, or the application exits. Changing or deleting a referenced jump host also stops its dependent forwards. Names and startup-toggle changes do not interrupt direct listeners. Browser mocks verify editing and lifecycle requests; isolated loopback protocol servers verify two-hop interoperability.

Profiles persist proxy selection, environment variables, notes and AI notes with the connection database. Proxy profiles support SOCKS5 and HTTP CONNECT, an optional device default, and explicit direct connections. Proxy passwords use the existing platform credential store and are never returned to the editor; blank password updates preserve the saved credential. Deleting a selected proxy causes an explicit error rather than an unnoticed direct connection. For saved jump routes, configure a proxy only on the first jump connection. The terminal's legacy jump-address mode retains its existing proxy-combination restriction.

The terminal sends environment variables as remote session requests, not as local process variables. The server must allow them. At most 64 unique variables and 32,768 total bytes are accepted; names are identifiers and values cannot contain line breaks or null bytes. Each note field permits 16,384 UTF-8 bytes. AI notes accompany requests targeting that host as user-owned context, not permission grants. Environment variables and notes are not credential storage; avoid secrets.

Proxy credentials travel to the proxy using its protocol; these proxy protocols do not encrypt that initial exchange. Use a trusted local proxy or a protected network. Destination host-key verification remains mandatory. The terminal proxy helper accepts only validated identifiers and destination endpoints, keeps credentials out of command arguments, and bounds protocol headers and handshake duration. Diagnostics redact environment contents, notes and credentials.

Validation covers database round trips, remote argument escaping, authentication modes, protocol handshakes, malformed replies, timeout limits and credential serialization. Browser tests compare both themes and narrow/wide layouts, save and reopen full profiles, manage proxies, and verify independent cursor-blink preferences. Terminal and input-method cursor blinking default off and can be enabled separately under typography settings.

## Jump routes and interactive gateways

Choose a saved connection as the destination's jump connection. Referenced profiles can themselves reference another jump connection, up to eight hops; cycles, missing references and conflicting jump addresses are rejected. Every hop retains its own username, key, saved password and temporary authentication. File connections verify every host key and carry the destination handshake through encrypted forwarding channels. Updating a profile or clearing authentication retires cached file channels, including dependent routes; channel bindings include every hop and its credential revision. Dropping a destination connection cancels its relay chain.

The interactive terminal still uses the system client. A temporary configuration supplies each saved hop's non-secret address and key settings, with host-key confirmation enabled; passwords remain interactive and never enter command arguments or the temporary file. The file is removed when the terminal reader ends. Existing comma-separated jump addresses remain supported; backend address routes use the explicit username or the basic host-alias settings already understood by the importer. Use saved profiles for independent passwords and temporary key passphrases.

Authenticate services opens the shared dialog. Password and private-key passphrase authentication progresses from the first saved hop to the destination, retaining credentials separately. Server challenges (MFA) authenticates the whole destination route within one handshake per endpoint, supports multiple rounds and fields, respects the server's echo setting, and confirms unknown fingerprints before sending credentials. A changed known fingerprint remains a hard failure. Answers are cleared after submission and are never cached or replayed.

File browsing and monitoring serialize their operations on the retained authenticated destination transport, so refreshes do not request the code again. Closing the last dependent terminal, clearing authentication, changing an endpoint or proxy, or exiting the app retires that transport. An expired transport requests authentication again; mutations are never replayed. Transfers and managed forwarding still require independent authentication and do not reuse this blocking service transport. External approval and menu-only asset-selection flows remain terminal capabilities; a gateway menu does not imply forwarding, SFTP or resource access. Keep shell integration disabled for that gateway.

Service failures identify the original endpoint and stage: handshake, host fingerprint verification, authentication, opening SFTP or resource collection. Outer service errors preserve the failing jump host rather than replacing it with the destination.

The desktop backend on Windows uses bundled cryptography, including modern key and key-exchange support. Protocol regression checks repeat direct and routed handshakes using the same finite-field algorithm to detect intermittent key-exchange failures, alongside the authentication and service checks.

If a gateway leaves mouse reports, focus reports or application cursor keys enabled after entering a shell, choose Reset terminal input modes from the terminal context menu. This preserves the screen and connection and sends no remote command. Native keyboard negotiation uses the terminal parser on supported desktop platforms; diagnostic markers record mode metadata without input payloads.

Run the optional isolated protocol check with `uv run --with paramiko python scripts/test-ssh-jumps.py`. It uses disposable keys, loopback listeners and private trust files, covering independent password/key authentication, two-factor challenges at two hops and the destination, concurrent service reuse without reauthentication, files, resources, forwarding, unknown/changed fingerprints, cancellation, rejected answers, client launch configuration and connection cleanup.
